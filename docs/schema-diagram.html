Relationships (cardinality)

patients 1 ──< N appointments (fk_appt_patient): a patient has 0..N appointments; every appointment has exactly 1 patient.

doctors 1 ──< N appointments (fk_appt_doctor): a doctor has 0..N appointments; every appointment has exactly 1 doctor.

Exactly 3 tables. All columns NOT NULL except active_slot, cancelled_at, refund_percent, refund_amount.

table-level constraints and index
UQuq_appt_doctor_active_slot (doctor_id, active_slot) — a doctor never has two BOOKED appointments at one date/time
UQuq_appt_patient_active_slot (patient_id, active_slot) — a patient is never in two places at once
CKchk_appt_status_consistency: BOOKED ⇒ cancelled_at, refund_percent, refund_amount all NULL; CANCELLED ⇒ all three NOT NULL
FKfk_appt_patient, fk_appt_doctor: ON DELETE RESTRICT, ON UPDATE RESTRICT (refund history is never lost)
IXidx_appt_doctor_datetime (doctor_id, appt_datetime) — performance only, not a rule

RULE: a doctor cannot have two appointments at the same date/time

active_slot = appt_datetime when status = 'BOOKED', NULL when 'CANCELLED'.

UNIQUE (doctor_id, active_slot) → a 2nd BOOKED row for the same doctor and slot is rejected (ERROR 1062).

NULLs never collide → the cancelled record is kept and the slot can be booked again.

Same idea per patient: UNIQUE (patient_id, active_slot).

Normalization notes (3NF)

  • Spreadsheet: appt_ref → doctor_name → specialty, fee, room (and → patient email → name, phone) are transitive dependencies. They are removed by storing each doctor and patient once and keeping only doctor_id / patient_id on the appointment.
  • amount_paid is not the fee: it can be discounted (AP-002 paid 120.00 on a 150.00 fee), so it depends on the appointment, not the doctor.
  • † refund_amount is a deliberate financial snapshot of the money returned, written in the same UPDATE as refund_percent. chk_appt_refund_matches_percent makes it impossible for the two to disagree, so storing it cannot cause an inconsistency.
  • ‡ The date inside appt_ref is part of a printed label only; appt_datetime is the authoritative slot. appt_ref is a UNIQUE candidate key, never used for logic.
